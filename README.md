# Neovim config

Personal Neovim configuration built on **`vim.pack`** (the plugin manager
built into Neovim 0.12+). No lazy.nvim, no Mason — tooling is managed by Nix.

## Layout

```
init.lua                    entry point (load order documented inline)
lua/
├── config/                 core config, loaded before any plugin
│   ├── options.lua         leader, vim.o, diagnostic config
│   ├── keymaps.lua         global keymaps (plugin keymaps live with their plugin)
│   └── autocmds.lua        global autocmds (yank highlight)
├── util/init.lua           shared helpers (gh() GitHub-URL builder)
├── pack.lua                PackChanged build hooks (fzf-native, LuaSnip, treesitter)
├── plugins.lua             ordered loader for the specs below
├── matugen.lua             generated base16 palette + SIGUSR1 hot-reload handler
├── health.lua              :checkhealth module
└── plugins/                one file per plugin, grouped by purpose
    ├── lsp/                language servers
    │   ├── lspconfig.lua   standard vim.lsp.config/enable servers
    │   ├── jdtls.lua       self-managed (Java — nvim-jdtls + DAP)
    │   └── rnvim.lua       self-managed (R — session + own language server)
    ├── code/               changes how text is edited or checked
    ├── git/                version control (gitsigns)
    ├── nav/                finding things / moving to them
    └── ui/                 appearance (theme, statusline, cmdline, hints)
templates/
└── matugen.lua.tmpl        mustache template → generates lua/matugen.lua
```

### Where does a new plugin go?

| If it...                                              | put it in |
| ----------------------------------------------------- | --------- |
| configures a language server via `vim.lsp.config`      | `lsp/lspconfig.lua` |
| drives its own LSP/session lifecycle (jdtls, R.nvim)   | `lsp/<lang>.lua` |
| edits, formats, lints, or debugs buffer text           | `code/` |
| is about git state                                     | `git/` |
| you invoke to locate, jump, browse, or replace         | `nav/` |
| only changes appearance                                | `ui/` |

Then add one `require` line to `lua/plugins.lua` (order matters only where
noted there — mini before devicon consumers, base16 before matugen).

## Conventions

- **Eager loading.** Every spec calls `vim.pack.add { ... }` then `.setup {}`.
  There is no lazy/deferred loading; `vim.pack.add` installs synchronously on
  first run and updates via `:lua vim.pack.update()`.
- **Self-contained specs.** A plugin's install, setup, keymaps, autocmds, and
  buffer-local `on_attach` maps all live in that plugin's file. `config/keymaps.lua`
  holds only plugin-independent global maps.
- **One owner per keymap.** No LHS is defined twice (verified via audit below).
- **Keymap scheme** (groups declared in `ui/which-key.lua`):
  - `<leader>g`/`<leader>gh*` — git / git hunks
  - `<leader>c` — code (LSP, format `<leader>cf`, lint `<leader>cl`)
  - `<leader>d` — debug (`<leader>db` breakpoint, `<F5>`/`<F1-3>`/`<F7>`)
  - `<leader>f*` / `<leader>s*` — find / search (telescope), `<leader>sr` search & replace (grug-far)
  - `<leader>x*` — diagnostics / quickfix (trouble)
  - `<leader>u*` — UI toggles; `<leader>b*` — buffers
- **Formatting.** stylua with `.stylua.toml` (2-space, single quotes). Run
  `stylua lua/` after edits.

## Tooling via Nix

Language servers, formatters, linters, and debug adapters are **not** installed
by any plugin — they're expected on `$PATH` from Nix:

- LSPs: `nil`/`nixd`, `lua-language-server`, `bash-language-server`, `clangd`,
  `basedpyright`, `yaml-language-server`, `jdtls`, ...
- Formatters (conform): `alejandra` (nix), `stylua` (lua)
- Linters (nvim-lint): `statix`, `selene`, `shellcheck`, `ruff`, `clang-tidy`, ...
- Debug (nvim-dap): `delve` (Go), plus jdtls/R tooling for their languages

Add/remove servers in `lsp/lspconfig.lua`, formatters in `code/conform.lua`,
linters in `code/lint.lua`. Run `:checkhealth` to see what's missing.

## Theming (matugen)

Colors are generated by [matugen](https://github.com/sgoudham/matugen) from
`templates/matugen.lua.tmpl` into `lua/matugen.lua` (a base16 palette).
Neovim listens on **SIGUSR1**: when matugen regenerates the palette, send
`pkill -USR1 nvim` (or target specific PIDs) to hot-reload highlights without
restarting.

## Extending

1. Create `lua/plugins/<category>/<name>.lua` following an existing file.
2. `require 'plugins.<category>.<name>'` in `lua/plugins.lua`.
3. `:lua vim.pack.update()` to install; `nvim-pack-lock.json` pins revisions.
